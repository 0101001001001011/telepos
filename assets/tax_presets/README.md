# Налоговые пресеты: страна → штат → город

Готовые наборы налоговой настройки. Положить сюда файл `*.json` — значит
добавить страну, штат или город, **не трогая код**.

Решение заказчика 2026-09-21: «под каждый штат разработкой заниматься не
будем; пресеты потом сделаем, но они как всегда устареют, поэтому
пользователь должен иметь возможность всё установить сам».

Как устроен сам расчёт и почему именно так — в
`docs/internal/research/2026-09-21-tax-configuration-models.md` и
`lib/domain/tax/tax_resolution.dart`.

---

## Три правила, без которых пресеты вредны

### 1. Пресет — отправная точка, а не власть

Загрузка пресета **копирует** значения в настройку кассы. Дальше касса живёт
своей настройкой, и обновление продукта её не трогает.

Иначе вышло бы худшее: магазин настроил ставку под себя, приехало
обновление с «более свежим» пресетом — и налог в чеках поменялся сам, без
ведома владельца. Налог менять молча нельзя: за него отвечает не продукт, а
налогоплательщик.

### 2. Число — строка, а не число JSON

`"ratePercent": "8.25"`, не `8.25`.

Числа JSON — двоичные `double`, и 8,25 в них представима, а 0,1 уже нет. В
этом проекте деньги и ставки — `Decimal`, никогда `double`; пропустить
ставку через `double` значит внести ошибку в том самом месте, где она
дороже всего. Строка разбирается в `Decimal` точно.

### 3. Ставка не задаётся — она выводится

В пресете нет поля «ставка». Есть дерево юрисдикций и правила «эта
юрисдикция так относится к этой категории». Сумма получается сама, и
`expectedStandardRatePercent` — не расчёт, а **обещание**, которое сторож
проверяет, прогоняя пресет через настоящий движок.

## Формат

```json
{
  "id": "us-co-denver",
  "title": "Denver, Colorado",
  "countryCode": "US",
  "region": "CO",
  "city": "Denver",
  "taxTreatment": "exclusive",
  "hasFiscalisation": false,
  "currencySymbol": "$",
  "currencyBeforeAmount": true,
  "expectedStandardRatePercent": "9.15",
  "categories": [
    { "code": "standard",  "title": "Standard", "isDefault": true },
    { "code": "food-home", "title": "Food for home consumption" }
  ],
  "jurisdictions": [
    {
      "code": "us-co", "name": "CO State", "level": 1, "parent": null,
      "tillLocation": false,
      "rules": [
        { "category": null,        "kind": "taxed",  "ratePercent": "2.90" },
        { "category": "food-home", "kind": "exempt", "ratePercent": "0" }
      ]
    },
    {
      "code": "us-co-denver", "name": "Denver", "level": 3, "parent": "us-co",
      "tillLocation": true,
      "rules": [ { "category": null, "kind": "taxed", "ratePercent": "5.15" } ]
    },
    {
      "code": "us-co-rtd", "name": "RTD", "level": 4, "parent": "us-co",
      "tillLocation": true,
      "rules": [ { "category": null, "kind": "taxed", "ratePercent": "1.00" } ]
    }
  ],
  "validFrom": "2026-01-01",
  "source": "Denver Tax Guide Topic No. 70 (2026); Colorado DR 1002"
}
```

| Поле | Смысл |
| --- | --- |
| `id` | уникальный, из латиницы и дефисов |
| `countryCode` / `region` / `city` | три уровня выбора; `null` ниже — пресет на всю страну или весь регион |
| `taxTreatment` | `inclusive` — налог в цене (СНГ, ЕС); `exclusive` — сверху (США); `none` — нет |
| `hasFiscalisation` | есть ли в стране фискализация как обязанность кассы |
| `expectedStandardRatePercent` | что пресет **обещает** для обычного товара; сверяется движком |
| `categories` | ровно одна с `"isDefault": true` |
| `jurisdictions[].level` | 0 страна, 1 штат, 2 округ, 3 город, 4 спецрайон |
| `jurisdictions[].parent` | код родителя или `null` |
| `jurisdictions[].tillLocation` | касса стоит здесь; предки отмечаться не обязаны |
| `rules[].category` | `null` — все категории, у которых нет своего правила |
| `rules[].kind` | `taxed` / `zero` / `exempt`; по умолчанию `taxed` |
| `validFrom`, `source` | обязательны |

### Почему спецрайоны висят на штате, а не на городе

RTD (транспорт) и SCFD (культура) накрывают несколько городов сразу.
Вложить их в Денвер значило бы соврать о том, кого они покрывают, и
завести те же районы заново для каждого соседнего города.

Отсюда `tillLocation` отметкой, а не одним полем «где касса»: юрисдикций у
кассы больше одной.

### Почему `source` и `validFrom` обязательны

Пресеты стареют — это свойство, а не недостаток. Ставки Колорадо меняются
дважды в год, 1 января и 1 июля. Пресет без даты и ссылки невозможно
проверить: непонятно, устарел он или нет и где смотреть правду.

## Что проверяет сторож

`test/architecture/tax_presets_test.dart` читает **настоящие файлы** и
считает **настоящим движком**: он не складывает доли сам, а спрашивает
`resolveTax`. Сложить их в пробе значило бы повторить там ту арифметику,
которую она проверяет, — и пресет с правилом, которого движок не применит,
прошёл бы насквозь.

Отказывает разборщик на: ставке числом, ссылке на несуществующую категорию
или родителя, пресете без места кассы, двух категориях по умолчанию,
неизвестном виде правила и на «освобождено по ставке 2,9 %».

---

## Чего пресеты НЕ делают

* **Не утверждают облагаемость за пользователя.** Матрица SSUTA — сотни
  строк на штат и меняется постоянно. Пресет даёт механизм и числа со
  ссылкой на источник; отвечает за налог налогоплательщик.
* **Не разбирают адрес в юрисдикцию.** Касса стоит в одном месте, и её
  юрисдикции задаются при настройке.
* **Не заменяют консультацию.**
