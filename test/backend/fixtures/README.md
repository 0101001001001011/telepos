# Заведомо публичные ключи для тестов

Здесь лежит **закрытый ключ, который знают все**. Это не оплошность и не то, что
надо «вынести в секреты»: файлы существуют ровно затем, чтобы тест мог поднять
настоящее TLS-рукопожатие и настоящий разбор SAN, не заводя нативной библиотеки
`rk_pki` — а её под `flutter test` нет (см. `docs/internal/testing-notes.md`).

| Файл | Что это |
| --- | --- |
| `insecure_test_ca.crt` | корень, которому доверяет только тест |
| `insecure_test_leaf.crt` | лист, подписанный этим корнем |
| `insecure_test_leaf.key` | закрытый ключ листа, PKCS#8 без пароля |

Лист выписан на **и имя, и адрес** — `DNS:localhost`, `DNS:till-3.local`,
`IP:127.0.0.1`, `IP:192.168.1.50`, — потому что именно это соседство проверяет
`test/data/pki/subject_alt_names_test.dart`: сертификат, годный только по имени,
перестаёт работать в тот день, когда mDNS в сети режут.

## Почему срок сто лет, если браузер отвергает всё длиннее четырнадцати суток

Правило про четырнадцать суток — про `serverCertificateHashes` в браузере, и
этот лист туда не попадает: его предъявляет `HttpServer` в тесте, а проверяет
`HttpClient` в том же процессе. Короткий срок сделал бы из фикстуры бомбу с
часовым механизмом — набор бы позеленел сегодня и покраснел через неделю по
причине, к коду отношения не имеющей.

## Чем это не является

Ни один путь приложения этих файлов не читает: они лежат под `test/`, и на
кассе доверие строится корнем из `rk_pki`, выписанным на месте. Если этот ключ
однажды окажется где-то в `lib/` — это дефект, и искать его надо не здесь.
