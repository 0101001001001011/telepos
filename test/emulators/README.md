# Эмуляторы внешних зависимостей

Подобие внешней зависимости, **отличимое от настоящей только адресом**.
Заглушка, которая всегда отвечает «да», сюда не относится: она не эмулирует
зависимость, она её отменяет.

Правило раздела: **эмулируется зависимость, а не наш адаптер.** Точка
подстановки — самая дальняя, до какой можно дотянуться: сеть. Не интерфейс над
драйвером. Поэтому эмулятор — отдельный процесс, а правок в `lib/` — ноль.

Эмуляторов здесь два семейства: фискальный оператор WebKassa (ярус 0) и
железо — принтеры, ящик, весы, дисплей, терминал оплаты (задача 20). Ниже
сначала WebKassa, затем раздел «Эмуляторы железа».

---

## Первое, что укусит

**Впиши адрес — и выбери оператора.** `StoreFiscalSettingsSource.load()`
(`lib/data/usecases/fiscal/store_fiscal_settings_source.dart`) отдаёт настройки
из prefs **только если** `operatorType != none`; иначе падает на
`ThisPosFiscalSettingsSource`, а тот жёстко ставит `testMode: false` и
`baseUrl: pos.webkassaHost`. Кто впишет адрес эмулятора, не выбрав WebKassa,
получит чужой адрес и решит, что эмулятор не работает.

**Второе: поле «локальный модуль» перебивает адрес сервера.**
`WebKassaProvider._baseUrl` (`webkassa_provider.dart:47`) читает
`localModuleUrl` первым и на `baseUrl` не смотрит вовсе, если тот заполнен.

## Эмулятор WebKassa

```
dart run test/emulators/webkassa/emulator.dart \
    --port 8085 --host 127.0.0.1 \
    --cashbox SWK00000001 --reg-number 000000000001 \
    --login emul --password emul \
    --token-ttl 30s --vat off
```

Печатает на старте адрес для экрана фискальных настроек и адрес пульта.
`--host 0.0.0.0` — когда касса на другой машине.

За одним этим адресом стоят четыре подсистемы: фискальный чек, ЭСФ, СНТ и
ИС МПТ — все четыре ходят через `FiscalSettingsStore` и тот же `baseUrl`.

### Файлы

| Файл | Что это |
| --- | --- |
| `lib/emulators/webkassa/emulator.dart` | сервер: девять путей `/api/v4/*` + пульт `/_emul/*` + дверь `/_emul/stop` |
| `lib/emulators/webkassa/state.dart` | смена, счётчики, токены, дедупликация, журнал, пересчёт денег |
| `lib/emulators/webkassa/faults.dart` | вызываемые отказы и карта кодов |
| `webkassa/emulator.dart` | тонкая обёртка с `main()`: та же команда запуска, что и была |
| `webkassa/probe.dart` | `dart run`: 45 случаев через настоящий `WebKassaProvider` |
| `webkassa/emulator_test.dart` | сторож: карта кодов и девять путей против исходника продукта |
| `webkassa/live_till_test.dart` | живой проход: **вся касса** фискализует продажу из базы |

### Что чем проверяется

```
dart run test/emulators/webkassa/probe.dart            # 45 случаев, ~20 с
dart run test/emulators/webkassa/probe.dart --journal  # плюс журнал целиком
flutter test test/emulators/webkassa/                  # сторож + живой проход
```

Живой проход умеет ходить и на **внешний** эмулятор — тогда тот действительно
чужой процесс на чужом сокете:

```
dart run test/emulators/webkassa/emulator.dart --port 8085 --token-ttl 1h
TELEPOS_EMUL_URL=http://127.0.0.1:8085 flutter test test/emulators/webkassa/live_till_test.dart
```

### Пульт

Пульт стоит на `/_emul/*` намеренно: настоящая WebKassa там ответит 404,
поэтому проба, случайно нацеленная на боевой сервер, падает громко, а не
проходит молча. Магических сумм в запросе («999.99 значит откажи») нет и не
будет: такая сумма однажды приедет из настоящей продажи.

| Путь | Тело | Действие |
| --- | --- | --- |
| `POST /_emul/fault` | `{path, code, text, count, afterN}` | ответить кодом `code` на следующие `count` вызовов `path` |
| `POST /_emul/offline` | `{on, limit, supported}` | автономный режим; после `limit` документов — код 18; `supported: false` — код 1013 |
| `POST /_emul/latency` | `{ms}` | задержка перед ответом |
| `POST /_emul/kill` | `{count}` | закрыть сокет без ответа |
| `POST /_emul/malformed` | `{count}` | ответить не-JSON при HTTP 200 |
| `POST /_emul/http` | `{status, body, count}` | ответить чужим статусом с телом не-JSON (502/503/504/429 — то, что стоит перед оператором; 404 — не тот адрес) |
| `POST /_emul/shift` | `{open, locked, stale}` | смена закрыта / заперта / просрочена |
| `POST /_emul/block` | `{on}` | касса заблокирована оператором |
| `POST /_emul/mark` | `{code, status}` | статус кода маркировки |
| `POST /_emul/reset` | — | очистить состояние и журнал |
| `GET /_emul/state` | — | смена, счётчики, наличные в ящике |
| `GET /_emul/journal` | — | журнал запросов, ответов и доводов |

### Вызываемые отказы

Восемнадцать, по одному на каждую ветку `WebKassaProvider._mapError` плюс
`default`. Восемь из них возникают **сами**, из состояния, без пульта.

| Код | Как вызвать | Что открывает |
| ---: | --- | --- |
| 1 | логин/пароль не те, что `--login/--password` | `badCredentials` |
| 2 | `Token` пустой или чужой | `tokenExpired`, перевыпуск и очередь |
| 3 | подождать `--token-ttl` | то же, но естественным путём |
| 6 | чужой `CashboxUniqueNumber` | `cashboxNotFound` |
| 7 | `/_emul/block {on:true}` | `cashboxBlocked` |
| 8 | `MoneyOperation` изъятие больше остатка | `notEnoughMoney` |
| 9 | сумма позиций ≠ сумме оплат | `validation` — пересчёт |
| 11 | `/_emul/shift {locked:true}` | `shiftError` |
| 12 | `/_emul/shift {stale:true}` | `shiftError` |
| 13 | Z-отчёт при закрытой смене | `shiftError` |
| 14 | повторить `ExternalCheckNumber` | `duplicate` — **обе** ветки повтора |
| 15 | X-отчёт при закрытой смене | `shiftError` |
| 18 | `/_emul/offline {on:true, limit:1}` и два чека | `offlineLimitExceeded` |
| 1013 | `/_emul/offline {supported:false}` | `offlineNotSupported` |
| 999 | `/_emul/fault {code:999}` | `default` → `unknown` |
| −1 | `/_emul/kill` | `HttpException` (измерено; не `SocketException`) → `network` → **вся очередь** |
| −2 | `/_emul/latency {ms:31000}` | `TimeoutException` → `network` |
| −3 | `/_emul/malformed` | неразборный ответ → `network` |
| −4 | адрес без узла в настройках | `requestNotBuilt` — **не** очередь |
| −5 | `/_emul/http {status:503}` | 5xx/408/429 без кода оператора → `operatorUnavailable` → очередь |
| −6 | адрес `https://` к порту эмулятора | `HandshakeException` → `tlsRejected` — **не** очередь |
| −7 | сокетом не производится (`kCodesNotProducibleBySocket`) | сбой кода кассы → `clientFault` — **не** очередь |

### Деньги

Пересчёт с **нулевым допуском**: `line = round(Count × Price, 2) − Discount +
Markup`, `Σ line` обязана равняться `Σ Payments[].Sum`. Прощающий эмулятор —
это заглушка с дополнительным шагом.

Всё считается в `Decimal`. `WebKassaProvider._money` возвращает `num`, и при
нецелом значении это `double`; сложи эмулятор `jsonDecode`-нутые `double` — и
он внесёт **свою** ошибку и покраснеет на исправном коде. На это стоит сторож,
и поведенческий, и сканом исходника.

`--vat included|added|off` — сверять ли `Tax` при `TaxType == 100`. По
умолчанию `off`: формула «налог в цене» — **наше допущение**, а не
документированный факт, и совпадает с тем, что считает
`FiscalPositionBuilder.vatFromGross`, то есть проверяла бы наш код против него
же самого.

## Чего эмулятор не доказывает

Это важнее того, что он доказывает.

* **Что настоящая WebKassa ведёт себя так же.** Своего верного числа у него
  нет ни одного: пути, конверт и карта кодов сняты с нашего клиента и нашего
  разбора — с нашего понимания чужого протокола. Расхождение ловится только
  прогоном по `devkkm.webkassa.kz`, и эта задача остаётся отдельной и
  обязательной.
* **Что чек напечатан** и что документ принят настоящим оператором. Ни
  принтера, ни оператора здесь нет.
* **Что наши числа верны для покупателя.** Пересчёт сверяет сумму позиций с
  суммой оплат внутри одного конверта — обе половины пришли от кассы. Числа с
  экрана в конверте нет, сверять не с чем.
* **Поведение под нагрузкой**, недокументированные поля и собственные
  тайм-ауты WebKassa.
* **`correctionReceipt`** — провайдер отвечает `unsupported`, не спрашивая
  сервер.

## Найденные дефекты продукта

Оба закреплены в пробах **как дефекты**: проба сходится, пока дефект жив, и
разойдётся в день починки, потребовав переписать случай на верное поведение.
Правок в `lib/` этот ярус не делает.

1. **ПОЧИНЕНО 2026-09-13. Кириллица в теле запроса не доезжала до сервера
   никогда.** `_defaultSend` писал тело `request.write` под
   `Content-Type: application/json` без `charset`; `HttpClientRequest` в
   этом случае кодирует **latin1**, и первая русская буква давала
   `Invalid argument (string): Contains invalid characters`. `catch (e)`
   превращал это в `-3` → `network` → «в очереди», `success: true`. Теперь
   тело уходит байтами UTF-8 с `charset=utf-8`, а несобираемый запрос
   получает свой код `-4` → `requestNotBuilt` и в очередь не встаёт.
   **Урок:** набор не видел дефект по трём причинам сразу — четыре набора
   подставляли `send:` в обход `_defaultSend`; пробы по сокету брали
   латиницу, чтобы обойти находку; сама находка была закреплена в
   `probe.dart` как дефект, то есть **сходилась, пока дефект жив**. Живая
   приёмка нашла его заново через шесть дней. Постоянные пробы:
   `test/data/datasources/webkassa_api_client_utf8_test.dart`,
   `test/data/fiscal/cyrillic_receipt_fiscalized_test.dart`; сторож
   `test/architecture/http_body_is_bytes_test.dart`.
2. **Повтор чека показывает «фискализовано» без документа.** `_checkResult`
   (`webkassa_provider.dart:267-269`) на код 14 отвечает
   `FiscalResult.ok(fiscalSign: '')`; `FiscalServiceImpl._persistReceipt`
   выходит по `!result.hasFiscalSign`, строки в `WebkassaReceipts` не
   появляется. Кассир видит успех, документа нет, следа нет. Измерено на
   настоящей кассе в `live_till_test.dart`.

И один дефект, **предсказанный до прогона** и потому не считающийся находкой:
**чек с бонусом не сходится по суммам.** Бонус списывается с бонусного счёта
покупателя, а `LocalPaymentService._fiscalize` раскладывает оплаты только по
`AccountType.pos` (наличные) и `AccountType.customBank` (карта). Позиции при
этом строятся на полную сумму, `totalDiscount` конверту не отправляется вовсе.
Сумма позиций больше суммы оплат ровно на бонус — пересчёт обязан отказать
кодом 9. **Чинить пересчёт при этом нельзя:** он прав.

# Эмуляторы железа

Заведены задачей 20 плана «Полнота продажи». Решение заказчика дословно:
«Везде где что-то нужно внешнее, оно известно и мы просто это эмулируем и
всё, для нас же главное чтобы наш код работал. **Всегда должен быть
эмулятор.**»

## Три механизма подстановки, ни одного нового

Точка подстановки — **самая дальняя от нашего кода**. Довод измерен: если
подставить свой класс в реестр провайдеров, то сборка запроса, разбор кодов
ошибок, повторная авторизация и обёртка очереди не пройдутся ни разу —
проверялся бы эмулятор, а не касса.

| Механизм | Кого им подставляют | Правок в `lib/` |
| --- | --- | ---: |
| **Адресом** | фискальный оператор (ЭСФ/СНТ/ИС МПТ за тем же адресом), чековый принтер, принтер этикеток, денежный ящик (через принтер), терминал Kaspi | **0** |
| **Петлёй ОС** | весы, дисплей покупателя | **0** |
| **Виртуальным профилем** | HID-сканер, печать через спулер | 6 файлов |

Виртуальный профиль — самый дорогой механизм и потому самый узкий: **два
семейства из семи**, у которых нет ни адреса, ни COM-порта. Каждый профиль
сверх этих двух — признак, что кто-то пошёл лёгким путём; на это стоит
сторож (`emulated_profiles_test.dart`).

## Где живёт код эмулятора

С 2026-09-19 ESC/POS живёт в `lib/emulators/escpos/`, последовательные
приборы — в `lib/emulators/serial/`, фискальный оператор — в
`lib/emulators/webkassa/`. Решение заказчика:
эмулятор должен быть в комплекте с кассой, чтобы для проверки шаблона чека и
диагностики не приходилось ставить ничего лишнего. В `test/` осталась тонкая
обёртка с `main()`; **все команды ниже не изменились**.

Правило раздела это не отменяет. Оно требует, чтобы точка подстановки была
самой дальней — сетью, а не интерфейсом над драйвером. Эмулятор внутри
приложения открывает настоящий серверный сокет, и касса идёт к нему своим
`WifiPrinterManager`. Запрещено другое: подставлять поддельный
`PrinterManager` в контейнер зависимостей — тогда «работает на эмуляторе»
перестанет говорить что-либо о работе на железе. То же и у оператора:
подставленный `FiscalProvider` снял бы с проверки сборку конверта, карту
кодов и очередь — то есть ровно то, что вероятнее всего сломано.

**У фискального оператора есть запрет, которого нет у железа.** Встроенный
эмулятор ОФД включается, только пока касса не боевая: `testMode == true`
**или** не заполнены ни регистрационный, ни заводской номер. Решение
заказчика 2026-09-19: чек, «профискализованный» в подделку, выглядит
настоящим, а документа покупателю не даёт. Запрет стоит на двери
`BuiltinEmulatorHost.start`, включение и выключение пишутся в журнал кассы.
Командная строка этой двери не знает — и это не дыра, а разные пользователи:
сюда ходит разработчик, а направить кассу на адрес всё равно надо руками.

## Что чем поднимается

| Прибор | Команда | Порт |
| --- | --- | --- |
| Чековый принтер ESC/POS + денежный ящик | `dart run test/emulators/escpos/emulator.dart --port 9100 --control 9110` | 9100 |
| Принтер этикеток ZPL/EPL/TSPL | `dart run test/emulators/escpos/emulator.dart --labels --port 9101 --control 9111` | 9101 |
| Терминал Kaspi POS | `dart run test/emulators/kaspi/emulator.dart --port 8888 --control 8898` | 8888 |
| Весы | `dart run test/emulators/serial/emulator.dart --port COM9 --role scale --control 8899` | COM9 |
| Дисплей покупателя | `dart run test/emulators/serial/emulator.dart --port COM11 --role display --control 8900` | COM11 |
| Фискальный оператор | `dart run test/emulators/webkassa/emulator.dart --port 8085` | 8085 |

**9100 может быть уже занят, и не эмулятором.** На машине разработки его
слушает `dart devtools` — Flutter DevTools берёт 9100 по умолчанию, и живёт
он неделями. Измерено: `netstat -ano | grep :9100` показал слушателя,
запущенного двумя сутками раньше. Признак — «address already in use» при
запуске эмулятора; лечение — `--port 9200` (и то же число вписать в
настройках принтера), а не убийство чужого процесса. Набор этой ловушки не
видит: его эмуляторы поднимаются на порту `0`, то есть на любом свободном.

Пара виртуальных COM-портов — средство ОС, не наше: Windows — **com0com**
(пара `COM8 ↔ COM9`), Linux/macOS — `socat -d -d pty,raw,echo=0 pty,raw,echo=0`.
Кассе вписывается **первый** порт пары, эмулятору — второй.

## Дверь остановки — обязательна

У стенда её не было, и за сутки это дало три висящих процесса. У каждого
эмулятора она есть, и на это стоит сторож:

```bash
curl -X POST http://127.0.0.1:9110/_emul/stop
dart run test/emulators/escpos/emulator.dart --stop --control 9110
```

`Ctrl-C` тоже гасит. Гасятся **и клиенты**: сервер, закрытый без них,
оставляет порт занятым. Незакрытый COM-порт на Windows остаётся занятым до
конца сеанса, и следующий запуск падает на «доступ запрещён» — поэтому
`stop()` закрывает порт явно, а не полагается на сборщик мусора.

## Вызываемые отказы

**Эмулятор, который не умеет отказать, бесполезен**: ветка отказа
недостижима, и её сторожа зелены впустую. Магических значений в потоке
(«задание на 999 байт значит откажи») нет и не будет: такое задание однажды
приедет из настоящей продажи. Отказ назначается пультом — снаружи разговора.

### Чековый и этикеточный принтер, `POST /_emul/fault`

| Ключ | Что делает | Какую ветку продукта открывает |
| --- | --- | --- |
| `offline: true` | бит 3 ответа `DLE EOT 1` | «принтер сообщает, что он offline» |
| `outOfPaper: true` | биты 5 и 6 ответа `DLE EOT 4` | «в принтере закончилась бумага» |
| `coverOpen: true` | тот же бит «не в сети» | крышка (отдельного бита продукт не читает) |
| `reject: N` | задание принять и выбросить | журнал эмулятора, не продукт |
| `kill: N` | закрыть сокет без ответа | полуоткрытый сокет, `connectionFailed` |
| `silence: N` | не ответить на опрос | «принтер не ответил за N мс» |
| `garbage: N` | ответить байтом без маркера | «прислал байты, но ни один не ответ `DLE EOT`» |
| `latencyMs: N` | задержка перед ответом | медленный, но живой прибор |

Крышка и бумага **разведены намеренно**, и это допущение эмулятора:
настоящий принтер с кончившейся бумагой чаще всего объявляет себя «не в
сети», то есть тем же битом. Слепи их эмулятор — ветка «закончилась бумага»
стала бы недостижима, и её сторож был бы зелен впустую.

### Kaspi POS, `POST /_emul/fault`

**Карты кодов отказа у нас нет** — ни в дереве, ни в документации. Продукт
разбирает ответ как «первый байт `0x30` — успех, всё остальное отказ».
Поэтому **коды отказа эмулятора наши и выдуманные**, и ни одно число не
является утверждением о поведении настоящего терминала. Следствие для
продукта прямое: разбор обязан обрабатывать **любой** первый байт, отличный
от `0x30`, а не наш список. Сторож на это читает `_parsePurchaseResponse` из
исходника продукта.

| `refuse` | Первый байт | Что открывает |
| --- | --- | --- |
| `declined` | `0x31` | отказ с текстом |
| `insufficientFunds` | `0x32` | тот же путь, другой код и текст |
| `cardRemoved` | `0x33` | то же |
| `terminalBusy` | `0x34` | то же |
| `cyrillic` | `0x37` | **предел**: кириллица в ответе не доезжает |
| `framesOnly` | `[0x02,0x03]` | «Некорректный ответ» |
| `silence` | — | тайм-аут |
| `kill` | — | `SocketException` |
| `refuseConnect` | — | соединение не принимается |

Тексты отказа — **латиницей**, и это измеренное следствие, а не вкус:
`_parsePurchaseResponse` разбирает хвост через `String.fromCharCodes`,
побайтно. Эмулятор, отвечающий по-русски, показывал бы эту беду как **свою**
и прятал бы её.

Два отказа возникают **сами**, из состояния, без пульта: сумма ноль
(`0x35`) и «сторнировать нечего» (`0x36`).

### Весы и дисплей, `POST /_emul/fault`

| `refuse` | Что делает | Что открывает |
| --- | --- | --- |
| `silent` | не отвечать вовсе | «весы не отвечают» ≠ «вес не устоялся» |
| `neverSettles` | только неустоявшийся вес | вторую половину той же развилки |
| `overload` | `OL` | немедленный выход без ожидания тайм-аута |
| `garbage` | строка не того формата | `parseLine` возвращает `null` |

Вес назначается пультом: `POST /_emul/weight {"weight":"1.250","stable":true}`.
Число едет **строкой**: эмулятор, сложивший `double`, внёс бы свою ошибку и
покраснел на исправном коде.

Эмулятор **не выдумывает** перегрузку для диалекта `massaK`: маркера у него
в продукте нет, а ложная «перегрузка» останавливает продажу. Молчит — как
молчали бы настоящие весы. На это стоит сторож.

### Эмулятор спулера (виртуальный профиль), параметр привязки `emulRefuse`

`offline` → `connectionFailed`; `outOfPaper`, `coverOpen`, `writeFails` →
`deviceRefused`; `throws` → `unexpectedError`. Список **наш и выдуманный**: у
спулера ОС нет протокола с кодами.

### Эмулятор сканера, параметр привязки `emulRefuse`

`notFound` — файла нет; `unreadable` — чтение падает. «Сканирование» — это
дописать строку в файл: `echo 4870204370014 >> scanner.txt`. Файл читается
**с конца**: иначе первый запуск стенда высыпал бы в кассу весь вчерашний
журнал.

## Что чем проверяется

```bash
flutter test test/emulators/                       # эмуляторы и их сторожа
flutter test test/architecture/device_check_reachability_test.dart
```

`hardware_test.dart` — живой проход: **настоящие** `WifiPrinterManager`,
`LabelPrinterService`, `KaspiPosService`, `ScalesService` против эмуляторов
на **настоящих** сокетах. Ни одного подставленного транспорта — иначе
проверялся бы эмулятор.

## Найденные дефекты продукта

Оба закреплены в пробах **как дефекты**: проба сходится, пока дефект жив, и
разойдётся в день починки, потребовав переписать случай на верное поведение.
Правок в `lib/` по ним задача 20 не делает.

1. **`KaspiPosService.disconnect()` после каждой удачной оплаты
   выбрасывает `Bad state: Future already completed`.** `_onDataReceived`
   (`kaspi_pos_service.dart:147-150`) завершает `_pendingResponse` и **не
   обнуляет** его; `disconnect` (`:116`) безусловно зовёт `completeError` на
   том же, уже завершённом `Completer`. Итог: закрыть терминал после оплаты
   картой нельзя, `dispose()` кассы падает. Набор этого не видел, потому что
   все пробы вокруг Kaspi подставляют транспорт и до успешного ответа по
   настоящему сокету не доходят.

2. **Ценник с русским названием уходит на принтер мусором.**
   `LabelPrinterService._send` (`label_printer_service.dart:151`) пишет
   `Uint8List.fromList(page.codeUnits)` — коды UTF-16 обрезаются до байта.
   «Молоко» это `[0x41C, 0x43E, …]`, в сокет уходит `[0x1C, 0x3E, …]`, то
   есть управляющие символы; тенге `₸` (U+20B8) → `0xB8`. Штрихкод из цифр
   доезжает целым, поэтому дефект незаметен: этикетки «печатаются», сканер их
   читает, а имя товара — мусор. **Тот же класс, что latin1 в теле запроса к
   WebKassa**, и найден тем же способом.

## Два предела, записанные, а не замолчанные

* **Ветка «Пустой ответ от терминала» недостижима по TCP.** Сокет не
  приносит пустых пакетов: `_onDataReceived` вызывается только с непустыми
  данными, поэтому `response.isEmpty` в `_parsePurchaseResponse` не может
  сработать ни при каком поведении терминала. Эмулятор вызвать её **не
  может**, и заявлять, что может, значило бы врать зелёным цветом.
* **Кириллица в ответе Kaspi до кассира не доезжает** при любой кодировке,
  которую выберет настоящий терминал: хвост разбирается побайтно. Кассир
  увидит мусор вместо причины отказа.

## Чего эмуляторы железа НЕ доказывают

* **Что чек напечатан, этикетка встала по месту, ящик открылся, весы
  взвесили, деньги списаны.** Ни бумаги, ни соленоида, ни груза, ни банка.
* **Что настоящие приборы ведут себя так же.** Ни одного верного числа: все
  команды, биты и форматы сняты с **нашего** кода, то есть с нашего
  понимания чужих протоколов. Расхождение ловится только прогоном по
  настоящему железу, и эта задача остаётся отдельной и обязательной.
* **Что кодовая страница верна для конкретной модели.** `ESC t 17` — это
  CP866 у большинства, но не у всех.
* **Что петля COM-порта работает.** Пары виртуальных портов на машине набора
  нет, поэтому весы проверяются набором на уровне **строки протокола**, а не
  порта. Порт проверяется только живьём на стенде.
* **Что виртуальные профили выброшены из магазинного бинарника.** Это
  утверждение о компиляторе; оно **измерено** отдельно —
  `docs/internal/testing-notes.md`, раздел «Виртуальные профили и AOT».

# Эмулятор провайдера QR/СБП (задача 22)

Третий эмулятор дерева и третий раз, когда точка подстановки выбрана самой
дальней: **адрес**. Правок в `lib/` под него — ноль, и это сторожится
пробой («продукт не знает про этот эмулятор ни имени, ни пути»).

```
dart run test/emulators/sbp/emulator.dart --port 8890 --control 8900
dart run test/emulators/sbp/emulator.dart --stop --control 8900
```

## Форма протокола ВЫДУМАНА, и это надо знать первым

Единого протокола СБП/QR у нас в дереве нет, договора с провайдером нет,
документации нет. Пути `/sbp/v1/*`, имена полей и коды состояний
**придуманы здесь**. Ни одно из них не является утверждением о поведении
настоящего провайдера — ровно как выдуманные коды отказа у эмулятора
Kaspi.

**Что этот эмулятор проверяет по-настоящему — не форму, а ВРЕМЯ.**
Подтверждение приходит после вопроса, может опоздать, не прийти вовсе,
прийти дважды и прийти после того, как касса сдалась. Это свойства не
протокола, а самого способа оплаты, и они одинаковы у любого провайдера.
Форму можно будет переписать под настоящий договор за час; разбор времени
переписывать не придётся.

## Вызываемые отказы

| Пульт | Что делает | Что открывает в продукте |
| --- | --- | --- |
| `POST /_emul/pay` | покупатель заплатил | счастливый путь |
| `/_emul/pay {afterMs}` | заплатил **позже терпения кассы** | «оплачено после того, как касса сдалась» |
| `/_emul/pay {times: 2}` | подтверждение **дважды** | деньги не берутся второй раз |
| `/_emul/pay {amount}` | заплатил **меньше** | «оплачено частично» |
| `/_emul/decline` | покупатель отказался | `failed` с названной причиной |
| `/_emul/expire` | срок вышел на той стороне | `expired` |
| **ничего не делать** | **молчание покупателя** | терпение кассы кончается |
| `fault: silence` | молчание провайдера | `qr_timeout` (транзиентный) |
| `fault: kill` | связь оборвана без заголовков | `qr_network` (транзиентный) |
| `fault: refuseConnect` | сокет не принят | `qr_network` |
| `fault: garbage` | тело не разбирается | `qr_malformed_reply` (НЕ транзиентный) |
| `fault: busy` | 503 | `qr_provider_busy` |
| `fault: unknownIntent` | 404 | `qr_unknown_intent` |
| `fault: rejected` | 422 | `qr_rejected` |
| `fault: reverseUnsupported` | 501 | `qr_reverse_unsupported` — отказ **значением** |
| `fault: http500` | 500 | `qr_rejected` |

**Молчание покупателя — не команда пульта, а её отсутствие**, и это
правильно: провайдер, у которого нельзя «ничего не делать», не умеет
воспроизвести самый обычный исход QR-оплаты — покупатель передумал.

## Найденные дефекты — три, и ни одного чтением

1. **`kill` рвал связь ПОСЛЕ заголовков.** Клиент получал законный 200 с
   пустым телом, продукт разбирал его как `qr_malformed_reply` (отказ **не**
   транзиентный) и **хоронил намерение**, при котором деньги могли уже
   уйти. Отказ, притворяющийся другим отказом, хуже отсутствующего: он
   красит сторожа зелёным по неверной причине. Лечение —
   `detachSocket(writeHeaders: false)`.
2. **Проба про обрыв связи не звала `awaitOutcome` вовсе.** Ставила отказ,
   ждала 120 мс, смотрела на строку — ни одного опроса не случалось, и она
   была бы зелена при любой поломке. Зелёный цвет означал «не смотрели
   туда».
3. **`reverseUnsupported` был в списке пульта и не был в разборе.** Возврат
   проходил там, где обязан был отказать значением.

## Дверь остановки

`POST /_emul/stop`, `Ctrl-C`, `--stop`. Снимает и **отложенные
подтверждения** (`/_emul/pay {afterMs}`): таймер, переживший тест, — тот же
висящий процесс, только без порта.

Порты в наборе берутся **нулём** — операционная система выдаёт свободный.
Прибитый номер даёт «Address already in use» ровно тогда, когда соседний
сеанс гоняет тот же файл, и выглядит это как дефект продукта.

## Чего этот эмулятор НЕ доказывает

* **Что деньги списаны.** Банка здесь нет.
* **Что настоящий провайдер называет состояния этими словами.**
* **Что QR-код читается телефоном.** Изображения нет — только строка
  нагрузки.
* **Что вебхук доедет.** Здесь только опрос, и это не упущение: вебхук
  требует адреса кассы, доступного провайдеру снаружи, а у кассы в магазине
  такого адреса нет. Опрос работает везде; вебхук работал бы на стенде и не
  работал бы в магазине, а разница обнаружилась бы на деньгах покупателя.
